Контекст (вопрос 5): главный страх владельца салона — «бот запишет не туда, клиент придёт, салон потерял деньги и репутацию». Ниже 4 варианта формулировок для договора + сервисные меры. После выбора зафиксирую вариант в CONTRACT_PDN_TEMPLATE.md (раздел 12) и оферте.

1Вариант 1. «Как есть» (минимальный)

  • Сервис предоставляется «как есть»; прямые убытки от ошибок бота не компенсируются.
  • Гарантии: полный лог диалогов и действий, экспорт по запросу, расторжение в любой момент с возвратом остатка месяца.
  • Плюс: просто и безопасно для нас. Минус: слабый аргумент против конкурентов (у Likesoft «стоп без претензий»).

2Вариант 2. Лимит ответственности = стоимость тарифа (рекомендую как базу)

  • Совокупная ответственность за календарный месяц ≤ суммы оплаченного тарифа за этот месяц (или setup — если он больше).
  • SLA-компенсация: простой сервиса > 4 ч в рабочие часы салона = +1 день сервиса бесплатно (начисляется автоматически).
  • Плюс: стандартный уровень B2B-SaaS, не пугает юристов салона. Минус: не «продающая» формулировка.

3Вариант 3. Компенсация подтверждённых инцидентов

  • Ошибка подтверждена логом (двойная бронь по вине сервиса; потерянный звонок из-за сбоя на нашей стороне > 30 мин в рабочее время) → компенсация 1 000–2 000 ₽ за инцидент, кумулятивно ≤ тариф месяца.
  • Плюс: сильный продающий аргумент. Минус: операционная нагрузка (разбор споров), риск злоупотреблений; требует чёткого определения «инцидента» в договоре.
  • Требует: журнал аудита с фазы 1 (кто/что/когда), иначе спор не разрешить.

4Вариант 4. Гарантия эффекта (только для пилотов)

  • «Не спасли ни одной записи за платный месяц пилота — месяц бесплатно / возврат setup» (приём рынка пилотов).
  • Плюс: снимает возражение «а вдруг не сработает». Минус: нужен замер «до/после» (базовая линия, фаза 4), иначе условие спорное; риск потерь на салоне с кривыми данными.
  • Применимо к пилотным салонам, не к постоянным договорам.

5Рекомендациярекомендация

Вариант 2 — в договор по умолчанию + Вариант 4 — только для пилотных салонов (30 дней) + журнал аудита с фазы 1, чтобы любой спор решался логом. Вариант 3 можно добавить позже, когда появятся ресурсы на разбор инцидентов.

6Открытые пунктыоткрытые пункты

  1. Выбор варианта(ов).
  2. Порог SLA (4 ч?) и определение «рабочих часов салона» (берём из ЛК).
  3. Зафиксировать в договоре: данные, подтверждённые салоном в ЛК (прайс, расписание, FAQ), — зона ответственности салона; ошибки из-за неактуальных данных — не инцидент.
