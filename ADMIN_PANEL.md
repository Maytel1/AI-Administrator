# Веб-панель «Дежурный24» — личный кабинет точки и админка команды

Фаза 4, дата: 30.09.2026. Реализовано: **MVP read-only** — панель работает на
настоящих данных (PostgreSQL, `admin_core`), поднимается одним сервисом в
локальном стеке: `docker compose up -d web` → http://localhost:8082/today

## 1. Референс: что посмотрели

Источник вдохновения — демо-панель автосервиса <https://avto-panel.demo.aivinity.ru/today>.
Сайт оказался SPA на React/Vite (собранный бандл `/assets/index-*.js`, 152 КБ),
поэтому интерфейс разобран по бандлу: 21 маршрут, 252 русские строки UI,
токены темы из CSS.

| Что в референсе | Что взяли | Что не берём и почему |
|---|---|---|
| Разделы: Сегодня, Заказы, Клиенты, Сотрудники, Задачи, Отчёты, Настройки | Навигацию по 8 разделам с активным пунктом | Канбан заказов, скла��, кассу, смены, зарплаты — это учётная система цеха, не наша задача |
| Тёмная тема: `#0c0d11` / карточки `#16171d` / радиусы 6-10-14 | Токены и плотность сетки один в один | — |
| Акцент `#7c3aed` (фиолетовый) | **Свой акцент `#4f46e5`** (фирменный `landing/styles.css`) | Копировать чужой фирменный цвет нельзя — это отстройка |
| Плитки показателей + «всё укладывается в срок» | Плитки с загрузкой мастеров и долей бота | Формулировку «всё укладывается» не рисуем: слоты — это план, а не факт |
| Демо-стенд со сбросом, вход по ссылке | Вход по паролю + переключатель салона (тенанта) | Публичный демо-стенд с чужими данными опасен (ПДн) |
| Чек-листы по машинам, аудит операций | **Журнал аудита** (у нас `audit_log`) | — |
| Иконки lucide, React, Recharts | Ничего: серверный HTML + свой CSS | Нет node в контуре и в CI; панель должна подниматься одной командой |

## 2. Что сделано у нас

Сервис `docker/services/web` (aiohttp, как health-сервер у bot-service).
Вся логика вынесена в `admin_core/web` — она тестируется обычным pytest без
порта и без HTTP; сервис остался тонким транспортом.

| Раздел | Что показывает | Источник |
|---|---|---|
| **Сегодня** | 6 плиток: записи, выручка, «сколько сделал бот», диалоги, новые клиенты, записи на 7 дней; загрузка мастеров; расписание дня | `bookings`, `dialogs`, `clients`, `services` |
| **Записи** | Лента ±30 дней, фильтр по статусу ссылками | `bookings` + справочники |
| **Клиенты** | Карточки: визиты, последний визит, очередь, флаг предоплаты, заметки | `clients` |
| **Прайс** | Услуги, длительность, цены — то, что бот озвучивает | `services` |
| **Мастера** | Команда и рабочие дни (из них нарезаются слоты) | `masters`, `working_hours` |
| **Диалоги** | Лента диалогов + раскрытая переписка клиент↔Анна | `dialogs`, `dialog_messages` |
| **Аудит** | Журнал: кто, что, когда — основа для разбора споров | `audit_log` |
| **Настройки** | Тариф, CRM, таймзона, режим бота, версия | `salons` |

Особенности:
* **время салона** — границы суток считаются в `salons.timezone` (Asia/Yekaterinburg),
  в БД уходит UTC: «Сегодня» у тюменской точки — это тюменские сутки;
* **изоляция по `salon_id`** в каждом запросе, переключатель салона в шапке;
* **доступ** — пароль `WEB_PANEL_PASSWORD`, сессия в httponly-cookie на 12 часов,
  пароль сверяется `hmac.compare_digest`; без входа разделы отдают форму, а не данные;
* **устойчивость** — ошибка БД не роняет сервис, а отдаёт заглушку и счётчик `page` в метриках;
* **ПДн** — весь текст проходит через `html.escape` (в панель попадают имена и телефоны).

## 3. Доступ и команды

```powershell
cd docker
# пароль и порт — в docker/.env (в git не попадает)
docker compose up -d web          # http://localhost:8082/today
```

| Переменная | Смысл |
|---|---|
| `WEB_HTTP_PORT` | порт панели на хосте (по умолчанию 8082) |
| `WEB_PANEL_PASSWORD` | пароль входа; **если не задан — вход закрыт полностью** |

Проверки: `docker compose exec -T cli pytest tests -q` (тесты панели в общем прогоне),
`/health` и `/metrics` — на соседнем порту `8083`.

## 4. Чего сознательно нет в MVP

1. **Правок данных** (CRUD): расписание, услуги, FAQ, сотрудники, роли — фаза 4;
2. **Ролей и TOTP-2FA** — сейчас один пароль на панель; для прода обязательно (план, §8.2);
3. **Графиков и отчётов** — графики понадобятся, когда накопятся месяцы данных;
4. **Заметок и комментариев администратора** — отдельная сущность в следующей итерации;
5. **Звонков и аудиозаписей** — фаза 3 (голос), панель их покажет позже.

## 5. Дорожная карта панели

| Шаг | Что | Приоритет |
|---|---|---|
| 1 | Правка расписания и услуг из панели (те самые «правки расписания/услуг/FAQ» из плана) | высокий — владелец сам настраивает точку |
| 2 | Роли: владелец точки / администратор / наша команда + изоляция прав | высокий (безопасность) |
| 3 | Статусы записей: подтвердить, отменить, пришёл/не пришёл | высокий — панель должна закрывать рутину |
| 4 | Диалоги: поиск по тексту, метки качества, экспорт | средний |
| 5 | Отчёты: выручка, загрузка, конверсия бота | средний |
| 6 | Графики (дневной/недельный) | после накопления данных |
| 7 | Биллинг: тарифы, триал, смена тарифа | высокий (решает №10 из плана) |
