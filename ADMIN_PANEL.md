# Веб-панель «Дежурный24» — личный кабинет точки и админка команды

Фаза 4, дата: 30.09.2026. Реализовано: **MVP с правками** — панель работает на
настоящих данных (PostgreSQL, `admin_core`) и позволяет менять расписание,
цены и статусы записей. Запуск: `docker compose up -d web` → http://localhost:8082/today

## 1. Референс: что посмотрели

Источник вдохновения — демо-панель автосервиса <https://avto-panel.demo.aivinity.ru/today>.
Сайт оказался SPA на React/Vite (собранный бандл `/assets/index-*.js`, 152 КБ),
поэтому интерфейс разобран по бандлу: 21 маршрут, 252 русские строки UI,
токены темы из CSS.

## 2. Что сделано у нас

Сервис `docker/services/web` (aiohttp, как health-сервер у bot-service).
Вся логика вынесена в `admin_core/web` — она тестируется обычным pytest без
порта и без HTTP; сервис остался тонким транспортом.

| Раздел | Что показывает | Правки |
|---|---|---|
| **Сегодня** | 6 плиток: записи, выручка, «сколько сделал бот», диалоги, новые клиенты, записи на 7 дней; загрузка мастеров; расписание дня | кнопки **Подтвердить / Выполнена / Отмена** прямо в строке |
| **Записи** | Лента ±30 дней, фильтр по статусу | те же кнопки статуса; отмена сразу освобождает слот |

| **Настройки** | Тариф, CRM, таймзона, режим бота, версия | — |

### Как устроены правки
1. **Одна точка входа** `POST /actions` → `admin_core.web.actions.apply_form`:
   разбор формы, валидация, понятный человеку результат;
2. **Бизнес-правила — в CRM** (`InternalCRM.set_booking_status`, `update_service`,
   `set_client_flags`, `set_working_hours`): там же проверка принадлежности салону;
3. **Каждая правка пишется в `audit_log`** с актором вида `owner:boss@example.com` —
   в разделе «Аудит» видно, кто именно правил;
4. **Салон берётся из сессии, а не из формы** — подменить `salon_id` нельзя;
5. **CSRF**: токен = HMAC(серверный секрет, токен сессии), сравнение константным временем;
6. **Права проверяются дважды**: недоступные кнопки не рисуются (`PageCtx.may`), а прямой
   POST от чужой роли отбивается с сообщением и счётчиком `forbidden` в метриках;
7. **Пользователю — flash**: после редиректа «Маникюр сохранена: 1 900 ₽, 90 мин»,
   а ошибка — красным блоком с текстом причины (цена, длительность, время, статус);
8. **Ошибка БД не роняет страницу**: заглушка + `traceback` в лог сервиса + счётчик в метриках;
9. **Сторож подписей разделов**: `check_builder_signatures()` проверяет всех builders
   при старте — рассинхрон ловится на старте, а не «заглушкой» в HTTP;
10. **Изменения слышит бот**: сузили окно мастера → этого времени больше нет в слотах,
    которые бот предлагает клиентам (проверено сквозным прогоном).

### HTTPS и заголовки безопасности (сделано 30.09)

| Заголовок | Зачем |
|---|---|
| `Strict-Transport-Security: max-age=31536000` | браузер запоминает «только HTTPS» на год; ставится **только** под HTTPS |
| `Content-Security-Policy` | `default-src 'self'`, `frame-ancestors 'none'` — защита от кликджекинга и подгрузки чужих скриптов |
| `X-Content-Type-Options: nosniff` | браузер не угадывает типы файлов |
| `X-Frame-Options: DENY` | панель нельзя встроить в чужой iframe |
| `Referrer-Policy: no-referrer` | адреса страниц с ПДн не утекают наружу |
| `Cache-Control: no-store` | панель с клиентами не кэшируется в браузере и прокси |

* **Cookie сессии** получает флаг `Secure` только под HTTPS — иначе браузер её отбросил бы.
* **За обратным прокси** (nginx, Cloud Load Balancer) включается `WEB_TRUST_PROXY=1`:
  тогда `X-Forwarded-Proto` учитывается. **По умолчанию выключено** — иначе любой клиент
  мог бы подделать заголовок и получить HSTS и Secure-cookie по обычному http.
* **Локальная проверка TLS**: `powershell -File docker/scripts/make_dev_cert.ps1` →
  в `docker/.env` появляется `WEB_TLS_CERT=/app/certs/dev-cert.pem` и `WEB_TLS_KEY=…`,
  панель поднимается на `https://localhost:8082`. Каталог `docker/certs` в `.gitignore`.

### Управление командой из панели (сделано 30.09)
Владелец точки в разделе «Настройки → Команда точки»:
* **создаёт сотрудника**: e-mail, имя, роль — временный пароль генерируется сервером
  и показывается **один раз** (в URL не попадает: пароль лежит в памяти сессии 10 минут);
* **включает 2FA сотруднику** — секрет и `otpauth://`-ссылка показываются один раз;
* **отключает доступ** — последнего владельца точки отключить нельзя;
* роль `team` из панели **не выдаётся** — она наша внутренняя, создаётся только из CLI.

### Аудит безопасности (30.09) — что нашли и закрыли

| Находка | Риск | Что сделано |
|---|---|---|
| `back=//evil.example` в редиректе | **open redirect**: увод администратора на фишинг с настоящего домена | `safe_redirect()` — белый список разделов панели, отбиты `//host`, абсолютные URL, `\r\n`, обратные слэши |
| Неверный UUID в `service_id`/`booking_id`/`client_id`/`master_id`/`user_id` | **DoS**: `DataError` от asyncpg → 500 на любой мусорный ID | `_uuid()` валидирует до похода в БД, понятная ошибка вместо падения |
| Нет ограничений на вход | перебор паролей; для TOTP — до миллиона кодов за окно | `Throttle`: 5 попыток на логин и 20 на IP за 15 минут, ответ 429; неверный код 2FA тоже тратит попытку |
| Аварийный вход по `WEB_PANEL_PASSWORD` давал роль `team` | любой, кто знал общий пароль, видел **все** точки | работает только при пустой таблице `panel_users`; счётчик `bootstrap_closed` в метриках |
| `X-Forwarded-Proto` мог бы выдать HSTS и Secure-cookie по обычному http | подделка заголовка = ложное «защищённое» соединение | `WEB_TRUST_PROXY=1` **выключен по умолчанию** |

Проверено вживую (HTTPS): инъекция в id → 302 с ошибкой, таблицы целы; `//evil.example` → редирект остался на `/today`; 6 попыток входа → 6-я даёт **HTTP 429**; POST без CSRF → отказ; без cookie → форма входа без данных; `/health` не отдаёт паролей и секретов.

Открытые для прода (осознанно не сделано в MVP): TLS termination и HSTS на реальном домене, заголовок `Public Key Pinning`, журнал попыток входа в БД (сейчас счётчик в метриках), ограничение по captcha, ротация секретов.

### Роли и вход (сделано 30.09)

| Роль | Кто | Права |
|---|---|---|
| `owner` | владелец точки | всё в своей точке + управление доступом |
| `staff` | администратор | просмотр, статусы записей, предоплата и заметки клиента |
| `team` | наша команда | всё во всех точках (переключатель салона) |

* **Вход**: e-mail + пароль, при необходимости + код TOTP из приложения-аутентификатора.
  Пароль хранится только хешем PBKDF2-HMAC-SHA256 (240 000 итераций, соль на пользователя),
  TOTP — RFC 6238 с допуском ±1 окно (часы телефона спешат на минуту — не отказ).
* **Неизвестный логин и неверный пароль дают одну и ту же ошибку** — перебором не выяснить,
  кто существует.
* **Изоляция по тенанту**: владелец и администратор не выйдут за пределы своей точки,
  даже если подставят чужой `?salon=` (`salon_for_session`).
* **Создание учёток** — из CLI: `python cli.py --user почта --role owner --password … [--totp]`;
  пароль и TOTP-секрет печатаются один раз.
* **2FA обязательна для роли `team`** в продуктиве; для владельца точки включается по желанию.

Особенности:
* **время салона** — границы суток считаются в `salons.timezone` (Asia/Yekaterinburg),
  в БД уходит UTC: «Сегодня» у тюменской точки — это тюменские сутки;
* **изоляция по `salon_id`** в каждом запросе, переключатель салона в шапке;
* **доступ** — пароль `WEB_PANEL_PASSWORD`, сессия в httponly-cookie на 12 часов,
  пароль сверяется `hmac.compare_digest`; без входа разделы отдают форму, а не данные;
* **устойчивость** — ошибка БД не роняет сервис, а отдаёт заглушку и счётчик `page` в метриках;
* **ПДн** — весь текст проходит через `html.escape` (в панель попадают имена и телефоны).

## 3. Доступ и команды

```powershell
cd docker
# пароль и порт — в docker/.env (в git не попадает)
docker compose up -d web          # http://localhost:8082/today
```

| Переменная | Смысл |
|---|---|
| `WEB_HTTP_PORT` | порт панели на хосте (по умолчанию 8082) |
| `WEB_PANEL_PASSWORD` | пароль входа; **если не задан — вход закрыт полностью** |

Проверки: `docker compose exec -T cli pytest tests -q` (тесты панели в общем прогоне),
`/health` и `/metrics` — на соседнем порту `8083`.

## 4. Чего сознательно нет в MVP

1. **Ролей и TOTP-2FA** — сейчас один пароль на панель; для прода обязательно (план, §8.2);
2. **Создания и удаления сущностей** — услуги, мастера и клиентов пока не добавлять;
3. **Графиков и отчётов** — понадобятся, когда накопятся месяцы данных;
4. **Звонков и аудиозаписей** — фаза 3 (голос), панель их покажет позже;
5. **Массовых операций** — «подтвердить все на завтра» и подобное.
