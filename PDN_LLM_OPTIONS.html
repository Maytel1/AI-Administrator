Контекст (вопрос 16). Противоречие: в DEVELOPMENT_PLAN.md заявлено «данные в РФ (152-ФЗ)», но LLM-ядро — gpt-4o-mini (OpenAI, США) и возможный DeepSeek (Китай). Отправка текста с именами/телефонами клиентов в зарубежный LLM = трансграничная передача ПДн.

1Юридическая рамка (коротко)

  • 152-ФЗ: первичный сбор ПДн россиян — локализован в РФ (ч. 5 ст. 18).
  • С 01.03.2023 уведомление РКН о трансграничной передаче обязательно.
  • С 30.05.2025 (ФЗ-266) для стран вне Конвенции Совета Европы (США, Китай) действует разрешительный порядок: нужно согласие РКН — «просто уведомить» недостаточно; на практике для OpenAI/DeepSeek почти нереально.
  • Следствие: отправлять ПДн клиентов в OpenAI/DeepSeek без обезличивания — высокий риск. Реалистичные пути — варианты 1, 2, 4, 5.

2Вариант 1. Минимизация/обезличивание перед LLM (дешёвый)

  • В промпт и tools не передаём имена/телефоны: «Клиент №42», номер остаётся в CRM. LLM работает с текстом запроса и не-ПДн данными (услуги, слоты, FAQ).
  • Транскрипт звонка содержит имя/голос → транскрипты храним в РФ (YC), в LLM шлём только фрагменты без ПДн.
  • Плюсы: остаёмся на gpt-4o-mini (качество/цена), юридически почти чисто. Минусы: инженерные усилия (гарантировать отсутствие ПДн в промптах); сценарий «запишите меня, меня зовут Анна, на 15:00» требует аккуратной маскировки.
  • Стоимость: ~0 ₽, ~1 неделя работы.

3Вариант 2. Полный переход на YandexGPT

  • LLM-ядро — YandexGPT (Pro/Lite): данные не покидают РФ, соглашение YC про 152-ФЗ.
  • Плюсы: юридически чисто; один вендор (YC) для голоса+хостинга+LLM; function calling есть. Минусы: качество русского диалога и tool-calling надо тестировать против gpt-4o-mini; вендор-лок.
  • Стоимость: сопоставимо (проверить прайс), 2–3 дня на замену SDK.

4Вариант 3. DeepSeek — не рекомендуем

  • Дёшево, но Китай: разрешительный порядок трансгранички, риск-профиль хуже. Допустимо только для не-ПДн задач (аналитика обезличенных логов, генерация текстов).

5Вариант 4. Локальная модель (Llama/Qwen on-prem в YC VM)

  • Всё в РФ, ноль трансгранички, максимальный контроль.
  • Минусы: GPU-инфраструктура (дорого для MVP), качество диалога ниже, скорость ниже. Вариант «позже», если появится требование клиентов.

6Вариант 5. Гибрид (рекомендую как целевой)

  • Дефолт: YandexGPT для всего, где есть ПДн (звонки, чаты клиентов).
  • gpt-4o-mini — только для обезличенных потоков (аналитика, генерация контента, тесты промптов, сравнение качества).
  • Плюсы: чисто и гибко. Минусы: два SDK, чуть сложнее код и биллинг моделей.

7Сопутствующие шаги (в любом варианте)

  • Уведомление РКН об обработке ПДн (мы — оператор для данных учётных записей салонов; по клиентам салонов — модель в CONTRACT_PDN_TEMPLATE.md).
  • Политика ПДн на сайте, согласия, уведомление «разговор записывается» (уже в фазах 0 и 3).
  • Аудио и транскрипты — приватный бакет YC Object Storage (РФ) с lifecycle; срок хранения — в OPEN_QUESTIONS.md (предложение: 90 дней).

8Рекомендациярекомендация

Фазы 1–2: Вариант 1 (обезличивание, работаем на gpt-4o-mini). Параллельно — сравнительный тест YandexGPT на наших 30 сценариях; к фазе 3 (голос) — Вариант 5 (или 2, если тест пройдёт убедительно). Финальные формулировки — у юриста.
